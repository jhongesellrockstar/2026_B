=====================================================================
OBJETIVO DEL VIDEO / EXPOSICIÓN
=====================================================================
Presentar el proyecto Callao Limpio como una aplicación académica construida con React + Vite, orientada al registro ciudadano de puntos con acumulación de residuos en el Callao.

La exposición debe explicar dos cosas al mismo tiempo:
1. Qué problema intenta representar el prototipo.
2. Cómo React permite construir la interfaz mediante componentes, estado, props, eventos, listas, persistencia local y estadísticas visuales.

La aplicación NO debe presentarse como sistema oficial de la UNAC, municipalidad o gobierno regional. Es un prototipo académico para Programación Web 2.

DIAPOSITIVA 3 - Problemática y propósito
Qué debe explicar:
- La aplicación se llama Callao Limpio.
- Representa un prototipo académico para registrar puntos con acumulación de residuos.
- El problema social de base es la presencia de residuos sólidos en espacios urbanos.
- La aplicación permite organizar reportes ciudadanos de forma simple.
- No es una aplicación oficial y no envía información a autoridades.

Captura sugerida:
- Cabecera principal de la aplicación.

Frase sugerida:
“Callao Limpio es un prototipo académico desarrollado para practicar React a partir de una problemática cercana: el registro de puntos con acumulación de residuos en el Callao”.

DIAPOSITIVA 4 - ¿Por qué React?
Qué debe explicar:
- React permite construir interfaces con componentes.
- En JavaScript básico se manipulaba el DOM directamente.
- En React, cambiamos el estado y React actualiza la interfaz.
- JSX permite escribir una estructura parecida a HTML dentro de JavaScript.
- Vite facilita crear y ejecutar el proyecto.

Captura sugerida:
- Carpeta src abierta o archivo main.jsx.

Frase sugerida:
“Antes creábamos o modificábamos elementos con JavaScript directo; ahora trabajamos con componentes y estado”.

DIAPOSITIVA 5 - Estructura general del proyecto
Qué debe explicar:
- src/main.jsx monta la aplicación.
- src/App.jsx es el componente principal.
- La carpeta components contiene partes separadas de la interfaz.
- App.jsx coordina los reportes, filtros y funciones principales.
- README.md permite ejecutar el proyecto en Windows 11.

Archivos que debe abrir:
- src/main.jsx
- src/App.jsx
- carpeta src/components

DIAPOSITIVA 6 - Objetivo funcional
Qué debe explicar:
- Registrar reportes.
- Visualizar reportes.
- Filtrar por estado.
- Cambiar un reporte de pendiente a atendido.
- Eliminar reportes.
- Guardar datos localmente.
- Mostrar estadísticas.

Captura sugerida:
- Vista principal de la aplicación.

Cierre de bloque:
“Con esta estructura general, pasamos a revisar cómo se registra un reporte desde el formulario”.

DIAPOSITIVA 7 - Formulario de registro
Qué debe explicar:
- El componente FormularioReporte.jsx contiene el formulario.
- Los campos son distrito, ubicación, tipo de residuo y descripción.
- Todos los campos son obligatorios.
- Al registrar, el reporte inicia como pendiente.

Captura sugerida:
- Formulario vacío.

Archivos que debe abrir:
- src/components/FormularioReporte.jsx

DIAPOSITIVA 8 - useState e inputs controlados
Qué debe explicar:
- useState permite guardar el valor actual de cada campo.
- value muestra el valor actual del estado.
- onChange actualiza el estado cuando el usuario escribe o selecciona.
- El formulario queda sincronizado con el estado de React.

Ejemplo que puede explicar:
const [distrito, setDistrito] = useState("");

Frase sugerida:
“El usuario escribe en el formulario, onChange captura ese cambio y setDistrito actualiza el estado”.

DIAPOSITIVA 9 - Envío y validación
Qué debe explicar:
- onSubmit ejecuta la función de envío.
- preventDefault evita que la página se recargue.
- trim se usa para validar que no haya campos vacíos o solo espacios.
- Si los campos son correctos, se crea un objeto reporte.
- El formulario no guarda toda la lista; envía el nuevo reporte hacia App mediante una prop.

Captura sugerida:
- Formulario lleno antes de pulsar Registrar reporte.

DIAPOSITIVA 10 - Objeto reporte generado
Qué debe explicar:
- Cada reporte contiene id, distrito, ubicación, tipo, descripción y estado.
- Date.now() se usa como identificador sencillo.
- estado inicia con “Pendiente”.
- Luego App.jsx agrega el nuevo objeto al arreglo de reportes.
- Después el formulario se limpia.

Cierre de bloque:
“El formulario construye el objeto reporte; ahora veremos cómo React muestra esa lista en pantalla”.

DIAPOSITIVA 11 - Props y comunicación
Qué debe explicar:
- Las props permiten pasar datos y funciones de un componente padre a un hijo.
- App.jsx mantiene los datos principales.
- ListaReportes recibe los reportes que debe mostrar.
- Reporte.jsx recibe la información de un solo reporte.

Frase sugerida:
“App es el componente principal; desde App viajan los datos y funciones hacia los componentes hijos”.

DIAPOSITIVA 12 - Listas con map()
Qué debe explicar:
- map recorre el arreglo de reportes.
- Por cada reporte genera un componente Reporte.
- key={reporte.id} ayuda a React a identificar cada elemento.
- Si el arreglo cambia, la interfaz también cambia.

Ejemplo conceptual:
reportes.map((reporte) => (
  <Reporte key={reporte.id} reporte={reporte} />
))

DIAPOSITIVA 13 - Tarjeta Reporte.jsx
Qué debe explicar:
- Cada reporte se muestra como una tarjeta.
- La tarjeta muestra distrito, ubicación, tipo, descripción y estado.
- También incluye botones para cambiar estado y eliminar.
- La información llega desde la prop reporte.

Captura sugerida:
- Una tarjeta de reporte visible.

DIAPOSITIVA 14 - Renderizado condicional
Qué debe explicar:
- Si no hay reportes, se muestra un mensaje vacío.
- Si el filtro no devuelve resultados, se muestra otro mensaje.
- El botón cambia de texto según el estado del reporte.
- React permite mostrar diferentes contenidos según los datos.

Captura sugerida:
- Lista vacía o filtro sin resultados.

Cierre de bloque:
“Ya sabemos cómo se crean y se muestran los reportes; ahora veremos cómo el usuario interactúa con ellos”.

DIAPOSITIVA 15 - Eventos principales
Qué debe explicar:
- onClick se usa para ejecutar acciones cuando el usuario pulsa un botón.
- Marcar atendido cambia el estado del reporte.
- Volver a pendiente permite retornar al estado anterior.
- Eliminar quita un reporte del arreglo.
- Filtrar cambia lo que se visualiza sin borrar datos.

Captura sugerida:
- Botones Marcar atendido y Eliminar.

DIAPOSITIVA 16 - map() y filter() en App.jsx
Qué debe explicar:
- map permite generar un nuevo arreglo cambiando solo el reporte correspondiente.
- filter permite quitar un reporte o seleccionar reportes por estado.
- En React no se debe modificar el estado directamente.
- Se crean nuevos arreglos para que React detecte el cambio.

Capturas sugeridas:
- Filtro Pendientes aplicado.
- Filtro Atendidos aplicado.

DIAPOSITIVA 17 - Persistencia con localStorage
Qué debe explicar:
- localStorage pertenece al navegador, no a React.
- Sirve para conservar datos aunque se recargue la página.
- JSON.stringify convierte el arreglo en texto.
- JSON.parse recupera el texto y lo convierte nuevamente en arreglo.
- useEffect guarda los reportes cuando cambia el estado.

Frase sugerida:
“No usamos backend. Los reportes se guardan únicamente en este navegador”.

DIAPOSITIVA 20 - Gráfico circular con CSS
Qué debe explicar:
- Se calcula el total de reportes.
- Se cuenta cuántos están pendientes y cuántos atendidos.
- Se calcula el porcentaje de cada estado.
- CSS usa conic-gradient para representar visualmente el porcentaje.

Fórmula simple:
porcentajePendientes = (pendientes / total) * 100

SLIDE FINAL DE RESPALDO - PREGUNTAS PROBABLES DEL DOCENTE
Slide asignado: 24
Puede responder cualquiera, pero se recomienda que lo maneje Jhon como cierre.
=====================================================================

Preguntas posibles:
1. ¿Qué diferencia hay entre estado y props?
2. ¿Por qué usamos componentes?
3. ¿Qué hace useEffect?
4. ¿Por qué no manipulamos el DOM directamente?
5. ¿Dónde se guardan los reportes?
6. ¿Qué pasa si se borra localStorage?
7. ¿Por qué no usamos backend?
8. ¿Por qué no usamos librerías de gráficos?

Respuestas breves:
- Estado: dato interno que cambia dentro de un componente.
- Props: datos o funciones que llegan desde un componente padre.
- useEffect: ejecuta una acción secundaria cuando cambia un dato, en este caso guardar en localStorage.
- No manipulamos DOM directamente porque React actualiza la interfaz a partir del estado.
- Los reportes se guardan en localStorage del navegador.
- Si se borra localStorage, se pierden los reportes.
- No usamos backend porque el alcance del curso es React básico.
- No usamos librerías de gráficos porque queríamos mantener la solución explicable con React, JavaScript y CSS.
